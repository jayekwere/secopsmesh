# Scoped cloud response extension contracts

This is a design specification, **not implemented cloud mutation capability**. The shipped executor accepts only the local application gate and disposable Kubernetes/Cilium adapters. Cloud collectors are read-only. Adding an adapter requires new typed policy, regression tests and separately authorized live acceptance; adding credentials alone cannot enable cloud response.

All future actions must bind an immutable provider resource ID, tenant, account/subscription/project, region, expected resource revision, original control snapshot, incident evidence digest, expiry and policy version into the approved plan. The executor must use a separate response identity and persist intent before mutation. Credentials and endpoints come only from operator-owned inventory. Unknown state is reconciled read-only; it is never a reason to repeat a write. Rollback is a distinct approved plan and must refuse a changed owner/revision.

| Adapter contract | Permitted typed action | Required readback and rollback boundary |
|---|---|---|
| AWS disposable EC2 lab | Replace one explicitly inventoried test ENI's security-group set with a precreated quarantine group; never create arbitrary firewall rules, stop instances or alter IAM | Bind account/region/ENI, expected original group set and quarantine-group ID. Re-read the exact association and use an independent scoped traffic probe. Restore only the original group set when current ownership and association still match. A separate role permits only the selected ENI and required descriptions; no broad remediation role. |
| Azure disposable VM lab | Associate one explicitly inventoried test NIC with an existing quarantine NSG; no subscription-wide policy or identity mutation | Bind subscription/resource group/NIC and original NSG/ETag. Use supported conditional writes and readback; require independent traffic proof and healthy control. Restore only when the current association still belongs to this action. If the selected API cannot enforce the conditional contract, deny the action. |
| GCP disposable Compute lab | Change only the approved test instance's network-tag set to include a precreated quarantine tag; no project firewall-rule or service-account changes | Bind project/zone/instance ID, original tags and provider fingerprint. Use fingerprint-conditional tag mutation. Read back tags and effective selected rules plus an independent probe; restore only if no concurrent tag change occurred. The response principal must be constrained to the selected lab resource. |

Network rule existence does not establish packet enforcement. Provider eventual consistency, unrelated outages, privileged account compromise and existing overlapping controls can invalidate a result. Every adapter must demonstrate baseline, enforcement, healthy control, replay rejection, interrupted-write recovery, ownership conflict and authorized rollback in an isolated authorized environment before its policy can be enabled. Destructive or irreversible actions are outside these contracts.
